## What this is

**Reps** — a strength-training workout logger built in **React Native + JavaScript on Expo**. It is being ported from an original SwiftUI concept. This app directory lives inside the `Reps` repo (at `project/app/`); the repo originated from a designer-skills toolkit, and the repo-root `CLAUDE.md` two levels up documents those design *skills*, not this codebase.

The **source of truth for the UI is screenshots**, not Figma, in `../brief/screenshots/` — a design-system sheet (colors + SF Pro type scale) plus a 9-screen flow. Note: those PNG filenames contain a narrow no-break space (` `) before "PM" — glob for them, don't hardcode the path. Project status, decisions, and run notes are tracked in `../STATE.md` — read it first; it is kept current.

## Expo version

Pinned to **Expo SDK 54** (RN 0.81, React 19.1) — do NOT bump it or `expo install --fix` toward a newer SDK. The physical iPhone runs via App Store Expo Go, which only supports SDK 54; a newer SDK breaks the phone (the App Store Expo Go lags npm). Read the versioned docs at https://docs.expo.dev/versions/v54.0.0/ before writing Expo-specific code. (`AGENTS.md` carries this same note.)

## Running the app

The app picks a **runtime UI tier** (`src/theme/useUITier.ts` → `liquid-glass | material-you | fallback`) per launch from ONE binary. Two ways to run it:

- **Expo Go (always `fallback`):** `npx expo start --go`, then scan the QR on the physical iPhone, or press `i`/`a`. Expo Go resolves to `fallback` by rule 1 of the tier table and can't load custom native modules — but it's the fastest loop, no build. Works on the SDK-54 iPhone.
- **Development build (shows the modern tiers):** `npx expo run:ios` (simulator) or `npx expo run:ios --device` (physical iPhone — needs Apple ID signing + USB-C). For Android use `./scripts/run-android.sh` — it wires up the JDK/Android SDK env (not on the default PATH), boots the Pixel_7 emulator if nothing is attached, then runs `expo run:android`. iOS 26 → `liquid-glass`; Android 12+ → `material-you`. After the first native build, `npx expo start --dev-client` hot-reloads JS into the installed dev app. **Verified:** the iOS 26.5 simulator dev build resolves to `liquid-glass` (`executionEnvironment: bare`, `isLiquidGlassAvailable(): true`); the Pixel_7 (API 37) dev build resolves to `material-you`.

> **`expo-dev-client` is installed**, so plain `npx expo start` defaults to **dev-build** mode — use `--go` for Expo Go. `ios/`/`android/` are git-ignored, regenerated by prebuild / `expo run:*`. Liquid Glass needs **Xcode 26 / iOS 26 SDK** to compile (`expo-glass-effect`); `@pchmn/expo-material3-theme` is Android-only and auto-links. Native modules are fine now (we're on a dev build) — just remember anything not in Expo Go means the `--go` path only ever shows `fallback`.

## Verifying changes

There is **no test runner or linter configured** (the `npm test`/lint scripts do not exist). Verify by:
- **Bundle check without a device:** `npx expo export --platform ios --output-dir /tmp/check` — catches import/syntax errors fast.
- **Typecheck:** `npx tsc --noEmit` — the theme layer and hooks are TypeScript (`tsconfig.json` extends `expo/tsconfig.base`).
- **Project health:** `npx expo-doctor`.
- **On-device:** screenshot the running app — `xcrun simctl io booted screenshot out.png` (iOS) or `adb exec-out screencap -p > out.png` (Android).
- **Visual style:** the hidden `Gallery` route (`src/screens/StyleGalleryScreen.js`) is a kitchen-sink screen that renders every shared component once — navigate to it to eyeball component changes before/instead of checking each real screen.

## Architecture

**Design tokens are a strict two-layer system — this is the central convention.**
- `src/theme/primitives.js` — raw values transcribed 1:1 from the screenshot (color ramps by number, the SF Pro type scale). Never reference these from screens.
- `src/theme/theme.js` — *semantic* tokens (`colors.bg`, `colors.accent`, `colors.textPrimary`, `typography.h1`, `spacing`, `radius`, plus `gradients`, `shadows`, `colors.hairline`, `borderCurve`) that map primitives to meaning. **Screens import only from `src/theme`** (the `index.js` barrel) and must use semantic tokens — no hardcoded hex/sizes. Brand accent is orange `#F05305`; the app is dark-only. Spacing/radius are an inferred 4-pt system (not measured from the screenshot) — confirm against real screens. Spread `borderCurve` (`'continuous'`) alongside every `borderRadius` for squircle corners (iOS honors it; Android falls back to a normal arc).

**Fonts are platform-native** — iOS sets no `fontFamily` (the system font *is* SF Pro; weights via `fontWeight`); Android maps each weight to a bundled **Inter** cut (SF Pro can't ship on Android) through the `w()` helper in `theme.js`. Fonts load in `App.js` via `useFonts`; import Inter weights by **subpath** (`@expo-google-fonts/inter/400Regular/...ttf`), never the package barrel — the barrel bundles all ~24 variants (~8 MB).

**The type scale is Apple HIG** (body 17, ~1.2× leading, HIG tracking) — `theme.js` exposes HIG-named tokens (`title1`–`title3`, `headline`, `callout`, `subhead`, `footnote`, `caption1`/`caption2`) plus legacy `h1`–`h6`/`caption`/`label` aliases mapped to the nearest HIG style. **For Dynamic Type, components that render text must read `useTypography()` (from the theme barrel), not the static `typography` import** — the hook scales each token's `lineHeight` by the OS `fontScale` so text reflows without clipping at large accessibility sizes (RN already scales `fontSize`). The static `typography` export is fine for non-render use, but any `<Text>` should use the hook.

**Navigation** (`src/navigation/RootNavigator.js`) is the app shell: a root native-stack wraps a bottom-tab navigator. Tabs = Home / History / Profile. Pushed over the tabs: `PlanDetail`, `WorkoutDetail`, `InSession` (presented as `fullScreenModal` — the core logging flow), `Settings`, `Calendar`. The React Navigation `DarkTheme` is overridden with the semantic color tokens so navigation chrome matches. `App.js` mounts this inside a `SafeAreaProvider`.

**Runtime UI tiers** (`src/theme/`) — the app renders modern native chrome when the runtime supports it, else a fallback, decided per launch from one binary. `useUITier()` returns `liquid-glass | material-you | fallback` (priority: Expo Go→fallback; Reduce Transparency→fallback; iOS≥26 + `isLiquidGlassAvailable()`→liquid-glass; Android≥31→material-you; else fallback) and is reactive to Reduce Transparency. `TierProvider` (in `App.js`) evaluates it once; surfaces read `useTier()`. **All per-tier styling is centralized** in `tiers.ts` + `TierSurface.tsx` — components don't hardcode per-tier values. Glass uses `GlassSurface` (real `expo-glass-effect`, opacity always 1); Material You uses `MaterialYouProvider` (dynamic palette); fallback uses the existing tokens. Native deps are **lazy-required only on their tier**, so Expo Go / fallback never load them. Tiered so far: `Card`, `ConfirmDialog`, in-session rest bar (full); the **tab bar** uses the native system bar (`react-native-bottom-tabs`, in `src/navigation/NativeTabs.js`, lazy-`require`d) on the modern tiers — Liquid Glass floating pill on iOS 26 (`liquid-glass`) and `BottomNavigationView` on Android 12+ (`material-you`) — and the JS `@react-navigation/bottom-tabs` fallback bar everywhere else (Expo Go, older OS). `NativeTabs` uses SF Symbols on iOS and async-loaded Ionicons image sources on Android (`@expo/vector-icons` has no sync `getImageSource`). `AppButton`/`Chip` (Material You only — glass-on-controls + `ScreenHeader` bar are TODO).

**Screens** (`src/screens/`) — one file per screen. Several are still `ScreenPlaceholder` stubs (`src/components/ScreenPlaceholder.js`) that only wire up navigation; `HomeScreen` and `InSessionScreen` are the built-out ones. Replace a placeholder's body with real UI as each screen is built.

**Data is mock and deliberately isolated.** `src/data/mock.js` (home/library) and `src/data/session.js` (active workout) return plain shapes that screens read. **Persistence will be Supabase** (`@supabase/supabase-js` + auth) — keep the screen-facing data shapes stable so the backend swaps in behind them without rewriting views. Product decisions already locked (see `../STATE.md`): kg/lb unit toggle (default kg), user-built routines plus optional pre-built ones, Supabase backend.

**Shared components** live in `src/components/` (e.g. `AppButton` with `primary`/`secondary`/`outline`/`ghost`/`destructive` variants) — reuse these rather than restyling buttons per screen. **All icons render through `Icon`** (`src/components/Icon.js`): it maps the app's icon names to SF Symbols on iOS (`expo-symbols`, which works in Expo Go) with an `@expo/vector-icons` glyph fallback per name. Never import `@expo/vector-icons` directly outside `Icon.js` — add the name mapping there instead.

**Intentionally kept, unwired:** the snap-bridge capture tooling (`hooks/useSnapTarget.ts`, `@unicorn-studio/snap-bridge`, `react-native-view-shot`) is not referenced by the app but is deliberately retained — don't remove it as dead code.
